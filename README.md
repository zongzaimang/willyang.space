# Will Yang Studio portfolio

The production site is the static portfolio generated by `tools/build-site.mjs`.
The earlier React/Vinext prototype under `app/` is retained for reference and is
not part of the default development or GitHub Pages build.

## Local development

Use Node.js 22 or later. The static build has no package dependencies.

```sh
npm run dev
```

Open `http://127.0.0.1:4173`. Edit `site.css`, `site.js`, `theme.js`, or the page
templates in `tools/build-site.mjs`. After template or project-data edits, run
`npm run generate` and refresh. Generated HTML is committed so the site also
works on an ordinary static server with JavaScript disabled.

```sh
npm run build
```

The deployable directory is `dist-static/`. The GitHub Pages workflow builds and
uploads only that directory, excluding local exports, tooling and dependencies.
Existing public project slugs and date-prefixed HC65 bookmarks are preserved.

## Project assets

`content/projects.json` remains the project registry; projects sort by
`startedAt`, newest first. Follow `MASTERGO_WORKFLOW.md` for exports. Run
`tools/generate-project-pages.ps1` after synchronizing assets; it now regenerates
all pages using the same shared template. A `00` image is a cover only; detail
images begin at `01` in export order. HC65 uses the existing transparent images
under `assets/hc65-uhe` until its new export directory exists.

Original images are never overwritten. Optional responsive WebP variants live
in `assets/responsive/`. To refresh them, use an installed `sharp` package:

```sh
node tools/optimize-images.mjs [path-to-sharp-entry-module]
npm run generate
```

The content hash in `content/image-variants.json` prevents stale variants from
being served after a source image changes. Without valid variants the generator
uses the original image, retaining intrinsic dimensions and lazy loading.

## Design and interaction

- Shared typography, spacing, colors and motion are defined in `site.css`.
- System/light/dark preference is applied before the first style paint and
  remembered across pages. Storage failures fall back safely.
- Motion follows `prefers-reduced-motion`; scrolling remains native.
- The header stays in document flow and has a direction threshold for hiding.
- Project images are ordinary links without JavaScript and accessible dialogs
  with fit-width/original-size controls when JavaScript is available.
- No social URLs are invented; contact remains the existing email address.

## Validation performed

Edge/Chromium desktop automation covered 9 pages × 12 widths × 2 themes (216
layout checks), from 320 to 2560 CSS pixels, plus 200% text enlargement at 320px,
all project image decoding, legacy query URLs, theme persistence, reduced motion,
dialog opening/zoom/Escape/focus return, and no-JavaScript content.

Screenshots and the local QA report are in ignored `outputs/`. These checks do
not establish Safari/Firefox or real-device coverage, WCAG certification, or
production Core Web Vitals. No deployment is implied by a successful local build.
